- direction: User wants an app where every member gets a personalized team of AI nutritionist agents.
- direction: User described separate agents for data collection/database maintenance and weekly diet plan generation.
- direction: User wants inputs including body weight, height, user goal, and related profile details.
- direction: User wants weekly full-day eating plans with nutrition facts, calories, item-level meal breakdowns, and daily shopping lists.
- technique: Started Assumption Stress Test.
- insight: The app needs a hard safety boundary between wellness planning and medical/disease treatment advice.
- idea: Add a health-risk intake gate for allergies, medical conditions, eating disorder risk, pregnancy, medications, food restrictions, and clinician involvement.
- idea: Add escalation rules that say when the AI must stop planning and recommend a registered dietitian, physician, or emergency support.
- idea: Build an evidence and calculation layer instead of letting a plan generator invent macros directly.
- idea: Track confidence in user data because stale or self-reported measurements can create unsafe or ineffective plans.
- idea: Create a profile timeline rather than a single user profile table so changes in weight, training, sleep, and goals are auditable.
- idea: Separate goal types into outcome goals, behavior goals, and constraints; athlete, powerlifter, healthy lifestyle, and aesthetics require different planning logic.
- idea: Add plan adherence capture after every day so the next week is based on actual consumption, substitutions, hunger, digestion, and energy.
- technique: Started Failure Modes.
- insight: The biggest product failure is not generating a plan; it is generating a plan the user does not follow.
- idea: Add a preference-learning agent that learns disliked foods, cooking skill, meal prep time, budget, cuisine, religious restrictions, and household context.
- idea: Add pantry and grocery-store constraints so shopping lists reflect what the user already has and what they can actually buy.
- idea: Add substitution logic for unavailable ingredients, eating out, travel days, and missed meals.
- idea: Add budget modes and local unit support because price, package sizes, and ingredients vary by region.
- idea: Add progressive onboarding so data collection does not feel like a medical form before the user gets value.
- idea: Add a plan critic agent that checks generated plans for macro targets, micronutrient gaps, fiber, sodium, meal variety, allergies, and contradiction with user constraints.
- idea: Add a "why this plan" explanation layer so users understand tradeoffs without turning the app into a wall of nutrition theory.
- technique: Started Agent Team Design.
- insight: Agent roles should map to accountable jobs, not persona labels.
- idea: Suggested agent roles: intake/profile agent, goal interpreter, nutrition calculation agent, weekly planner, meal/cuisine agent, shopping/pantry agent, adherence coach, safety/compliance guard, and plan auditor.
- idea: Use orchestration with traceable outputs rather than letting agents privately negotiate; each recommendation should have source inputs, assumptions, and checks.
- idea: Maintain a user-facing summary and a machine-facing nutrition state separately.
- idea: Add conflict resolution when two agents disagree, such as user preference versus nutritional adequacy.
- idea: Add versioned diet plans so users can compare changes and roll back.
- technique: Started Trust and Business Reality.
- insight: Health data privacy and regulatory positioning are first-order product requirements, not later legal polish.
- idea: Decide early whether the product is only a general wellness product or whether it will make disease, treatment, or diagnostic claims.
- idea: Build consent, data export, deletion, retention, breach response, and data-sharing controls into the first architecture.
- idea: Add professional review workflows if the product says "nutritionists" in a way users could interpret as licensed human care.
- idea: Add quality metrics: adherence rate, plan completion, weight trend accuracy, user energy/hunger ratings, grocery waste, and safety interventions.
- idea: Consider human expert escalation or review as a premium or trust-building feature.
- insight: Best next step is to convert this into a product brief or PRD with clear MVP boundaries.
- direction: User added a recipe agent responsible for creating recipes for every planned meal.
- decision: User narrowed the wellness MVP goals to fat loss and muscle gain only.
- decision: Both fat loss and muscle gain flows include target weight as an input.
- technique: Started MVP Constraint Refinement.
- insight: Narrowing goals to fat loss and muscle gain makes the product easier to keep in a wellness lane, but target weight alone is not sufficient.
- idea: Add target timeframe or preferred rate of change so fat loss and muscle gain plans can avoid unsafe or unrealistic weekly changes.
- idea: Add a goal feasibility check that compares current weight, target weight, timeline, age, sex, activity, training frequency, and adherence history.
- idea: Add guardrails for minimum calories, protein targets, expected weight-change ranges, and alerts when a target looks extreme.
- idea: For muscle gain, distinguish total target weight from lean-mass intent so the app does not blindly encourage aggressive surplus eating.
- idea: Recipe agent should convert meal slots into executable recipes with ingredient grams, servings, prep steps, cook time, equipment, allergens, substitutions, leftovers, and item-level nutrition.
- idea: Recipe agent should coordinate with shopping and pantry agents so recipes reuse ingredients and reduce grocery waste.
- idea: Weekly planner should choose meal structure and targets; recipe agent should produce the actual dish instructions and verify recipe nutrition against plan targets.
- direction: User requested a prompt to start the idea with the bmad-architecture skill.
- decision: Architecture handoff prompt should ask for Fast path with explicit assumptions and a lean architecture spine, not a full PRD.
- idea: Architecture prompt should emphasize wellness-only scope, fat loss and muscle gain MVP, target weight plus pace, recipe agent, deterministic nutrition logic, traceable agent outputs, profile timeline, plan versioning, privacy, safety, and auditability.
